1) GEOSPATIAL DATA

What is geospatial data?

It’s data that describes things that exist somewhere on Earth. A city, a hurricane track, a country boundary, a temperature reading — all of these can be stored as geospatial data. There are two fundamentally different ways to represent geography:

  • Vector data — describes discrete, bounded things using shapes (points, lines, polygons). Example: “California is this specific polygon shape.”
  • Raster data — describes continuous things using a grid of cells, like pixels in an image. Example: “The temperature at every point on a map.”

Section 1: Coordinate Reference Systems (CRS)

The core problem

The Earth is a 3D sphere. Maps are 2D. You have to decide how to “project” the sphere onto a flat surface — and every method distorts something (area, shape, distance, or direction). There is no perfect map projection.

Additionally, before you even project, you need a way to specify locations on the sphere. That’s what a Coordinate Reference System (CRS) does — it defines what the numbers (coordinates) actually mean.

Two types of CRS

Geographic CRS (GCS) — coordinates are in degrees of latitude and longitude. No projection has been applied; you’re working on the sphere.

Name Code Used by
WGS84 EPSG:4326 GPS, Google Maps, cell phones — the universal standard
NAD83 EPSG:4269 US government data, US Census shapefiles

Projected CRS (PCS) — coordinates are in meters or feet, because a projection has been applied to flatten the sphere. Used when you need accurate measurements on a local scale.

EPSG codes are just internationally standardized ID numbers for CRS definitions. EPSG:4326 = WGS84. Think of them like zip codes for coordinate systems.

Why does this matter?

If you have two datasets in different CRS, they won’t line up on a map. You have to transform them to match. Also, leaflet (the interactive map tool) only accepts WGS84 (EPSG:4326). If your data is in anything else, you must convert it first.

How to check/change CRS in R

# See what CRS an sf object currently uses
st_crs(my_sf_object)

# Transform to WGS84 (required before leaflet)
my_sf_object <- my_sf_object |>
  st_transform(crs = 4326)

# Change the projection used to DRAW a ggplot map (doesn't change the data)
ggplot(data = world2) +
  geom_sf() +
  coord_sf(crs = "+proj=moll")  # Mollweide projection — good for world maps
  # Other options: "+proj=cea", "+proj=ortho", "+proj=merc"

st_transform() actually converts the underlying coordinates. coord_sf(crs = ...) just changes how ggplot draws the map visually.

Sample Quiz Questions — CRS

Q1: You load a shapefile from the US Census Bureau. It uses NAD83 (EPSG:4269). You want to display it on a leaflet map. What must you do first?

A: Call st_transform(crs = 4326) to convert to WGS84 before passing it to leaflet.

Q2: True or False: coord_sf(crs = "+proj=moll") permanently changes the CRS of your sf data object.

A: False. It only affects how ggplot draws the map. The underlying data is unchanged.

Q3: What is the difference between a Geographic CRS and a Projected CRS?

A: A Geographic CRS uses degrees (lat/lon) on a sphere. A Projected CRS uses meters or feet on a flat surface — the sphere has been mathematically “flattened.”

Section 2: Vector Data and the sf Package

What is vector data?

Vector data represents geographic features as one of three geometry types:

  • Point — a single location. Example: a city, a fire station, a GPS waypoint.
  • Line (LineString) — a sequence of connected points. Example: a road, a river, a flight path.
  • Polygon — a closed shape. Example: a country border, a lake, a fire perimeter.

A collection of features (multiple points, or multiple polygons) is called a layer.

What is an sf object?

sf stands for simple features, which is an international standard for storing vector geospatial data. In R, an sf object is just a regular data frame with an extra column called geometry. Each row is one feature (one country, one fire, one city). Each column is an attribute (population, name, area). The geometry column stores the actual shape.

class(world2)
# [1] "sf"         "data.frame"
# It IS a data frame. You can use dplyr on it!

names(world2)
# [1] "sovereignt" "pop_est" "gdp_md" ... "geometry"
# The last column is always geometry

head(world2)
# Shows: Geometry type, Dimension, Bounding box, CRS
# Then the actual rows of data

Key facts about sf objects

  • One geometry type per object — you can’t mix points and polygons in the same sf object.
  • The geometry column is “sticky” — when you use filter(), mutate(), etc., the geometry column follows along automatically. This is useful, but can slow down pure data analysis.
  • Always carries CRS info — the sf object remembers what coordinate system it’s in.

Removing the geometry column (for speed during EDA)

# Clean way
dat_only <- st_drop_geometry(my_sf_object)

# The result is a regular data frame with no geometry column
# Use this when you want to do data analysis without slow spatial operations

Loading vector data from different sources

From the rnaturalearth package (pre-built world/country/state maps):

# World country outlines as polygons
world2 <- ne_countries(returnclass = "sf")
# returnclass = "sf" means: give me an sf object (not a plain data frame)

# US states
usa_states <- ne_states(
  country = "United States of America",
  returnclass = "sf")

# Filter to just California
cal_map <- ne_states(country = "United States of America", returnclass = "sf") |>
  filter(name == "California")

From the usmap package (includes Alaska and Hawaii, properly positioned):

us_states <- us_map(regions = "states")
# Columns: fips (state code), abbr (CA), full (California), geom (geometry)
# WARNING: This uses NAD27 projection (NOT WGS84). Must st_transform() before leaflet.

From a shapefile (downloaded from the internet, e.g., fire perimeters):

# A shapefile is NOT one file — it's a FOLDER of files
# Required files inside folder: .shp, .dbf, .shx
# Pass the FOLDER NAME to st_read(), not any individual file

cal_perims <- st_read("California_Fire_Perimeters_(1950+)")
# Output tells you: geometry type, number of features, number of fields, CRS

Sample Quiz Questions — sf Objects

Q1: You call filter(world2, continent == "Africa") on an sf object. What happens to the geometry column?

A: The geometry column follows along automatically (“sticky geometry”). The result is still an sf object with geometry for African countries only.

Q2: What is the difference between st_drop_geometry() and filter()?

A: st_drop_geometry() removes the geometry column entirely, returning a plain data frame. filter() keeps the geometry and returns an sf object, just with fewer rows.

Q3: You try to load a shapefile by calling st_read("data/fires.shp") but get an error saying the file is missing. What is most likely the problem?

A: Shapefiles are actually multiple files (.shp, .dbf, .shx, etc.) that must all be in the same folder. You should pass the folder name to st_read(), not an individual .shp file path. Also, required companion files might be missing.

Q4: True or False: An sf object can contain both point and polygon geometries at the same time.

A: False. Each sf object can only have one geometry type.

Section 3: Making Maps with ggplot() and geom_sf()

The basic idea

geom_sf() is a special ggplot geometry that knows how to draw sf objects. It automatically reads the geometry column and draws the appropriate shapes (points, lines, polygons).

# Simplest possible map — draws all world countries
ggplot(data = world2) +
  geom_sf()
# Output: a world map with country borders, gray fill, white background

Customizing fill and border color

# Static colors — not mapped to any data variable
ggplot(data = us_states) +
  geom_sf(fill = "steelblue", color = "white")
# fill = the inside color of each polygon
# color = the border/outline color

Adding text labels to the map

ggplot(data = us_states) +
  geom_sf() +
  geom_sf_text(aes(label = abbr), size = 3, color = "white")
# geom_sf_text automatically places labels at the centroid of each polygon
# abbr is a column in us_states that has state abbreviations like "CA", "TX"

Zooming in on a region

ggplot(data = world2) +
  geom_sf() +
  coord_sf(xlim = c(-130, -60), ylim = c(20, 55))
# xlim = range of longitudes (x-axis = east-west)
# ylim = range of latitudes (y-axis = north-south)
# This zooms into North America without dropping any data

Combining a map layer with regular data (e.g., storm paths)

ggplot() +                                          # empty ggplot — data specified per layer
  geom_sf(data = world2) +                          # sf layer: world map as background
  geom_point(data = storms75,                       # regular ggplot layer: storm positions
             aes(x = long, y = lat, color = name)) +
  geom_path(data = storms75,                        # connects points in order (draws paths)
            aes(x = long, y = lat, color = name)) +
  coord_sf(xlim = c(-110, -30), ylim = c(5, 65))   # zoom to North Atlantic

When mixing sf and non-sf layers, leave ggplot() empty and specify data = inside each geom_() call.

Choropleth maps — coloring polygons by a data value

A choropleth is a map where each region (state, country, county) is colored according to a numeric variable. Example: coloring US states by average income, or by number of fires.

The workflow:

  1. Get an sf object (the map shapes)
  2. Get a data frame with the values you want to color by
  3. Join them together (matching states to their values)
  4. Plot with aes(fill = your_variable)
# Step 1: get map shapes
us_states <- us_map(regions = "states")   # has columns: fips, abbr, full, geom

# Step 2: get data (e.g., average salary by state)
salaries <- read_csv("salaries.csv") |>
  mutate(Average = as.numeric(str_remove_all(Average, "[,$]")))
# str_remove_all removes $ and , characters before converting to number

# Step 3: join — sf object MUST be on the left side
joined <- inner_join(us_states, salaries, by = c("full" = "State"))
# "full" is the column name in us_states, "State" is the column name in salaries
# The result is still an sf object (geometry travels with the left table)

# Step 4: plot
ggplot(joined) +
  geom_sf(aes(fill = Average), color = "white") +
  theme_void()   # removes axis labels, gridlines — cleaner for maps

Color scale options for choropleth maps

# Smooth gradient between two colors
scale_fill_gradient(low = "#1b4bab", high = "#d7e1f5")

# Gradient with a midpoint (diverging — good for showing above/below average)
scale_fill_gradient2(low = "blue", mid = "white", high = "red", midpoint = 0)

# Multiple colors (e.g., from RColorBrewer — a library of curated color palettes)
scale_fill_gradientn(colors = brewer.pal(n = 7, name = "Purples"))
# brewer.pal(n, name) creates a vector of n colors from the named palette

# Discrete steps instead of smooth gradient (easier to read category boundaries)
scale_fill_stepsn(colors = brewer.pal(n = 7, name = "Purples"),
                  breaks = seq(45000, 80000, by = 5000))

# Viridis — colorblind-friendly palettes
scale_fill_viridis_c()    # _c = continuous data
scale_fill_viridis_b()    # _b = binned (discrete steps)
scale_fill_viridis_d()    # _d = discrete/categorical data
scale_fill_viridis_c(direction = -1)  # reverse the color direction

Sample Quiz Questions — ggplot maps

Q1: What is a choropleth map?

A: A map where geographic regions (countries, states, counties) are filled with a color that represents a numerical value of some variable — like income, population, or temperature.

Q2: You have an sf object us_states and a data frame df with a column State (state names) and value. Write the join command to combine them for a choropleth, knowing us_states has a column called full.

A: joined <- inner_join(us_states, df, by = c("full" = "State"))
The sf object must go on the left side.

Q3: What does theme_void() do to a ggplot map?

A: It removes all non-data elements — axis labels, tick marks, gridlines, background — leaving just the map itself. This is standard practice for maps since axes showing latitude/longitude are usually clutter.

Q4: What is the difference between scale_fill_viridis_c() and scale_fill_viridis_b()?

A: _c is for continuous data (smooth gradient). _b is for binned data (discrete color steps). Binned is easier for readers to assign a specific value range to a color.

Section 4: Interactive Maps with ggiraph (geom_sf_interactive)

The idea

ggiraph is a package that makes ggplot charts interactive by adding tooltips (text that appears when you hover). For maps, you swap geom_sf() for geom_sf_interactive(), then wrap the whole plot with girafe().

library(ggiraph)

# Step 1: Build the plot using geom_sf_interactive instead of geom_sf
gmap <- joined_data |>
  mutate(Label = paste0(full, ": $", Average)) |>   # create tooltip text
  ggplot(aes(fill = Average, tooltip = Label)) +     # tooltip goes inside aes()
  geom_sf_interactive(color = "white") +             # interactive version of geom_sf
  scale_fill_gradientn(colors = brewer.pal(n = 7, name = "Purples")) +
  theme_void()

# Step 2: Render as interactive HTML widget
girafe(ggobj = gmap)
# Output: a map where hovering over a state shows the tooltip text

For more complex tooltips with formatting:

geom_sf_interactive(aes(
  fill = winner,
  tooltip = sprintf("%s\nDem: %s%%\nRep: %s%%", full, DEMOCRAT, REPUBLICAN)
))
# sprintf() is like paste0() but lets you embed values into a template string
# \n = newline, %s = string placeholder, %% = literal percent sign

Sample Quiz Questions — ggiraph

Q1: Where does the tooltip argument go in geom_sf_interactive()?

A: Inside aes() — it must be mapped to a column name or expression, not a static string outside aes.

Q2: After building a ggplot with geom_sf_interactive(), what function do you call to make it actually interactive?

A: girafe(ggobj = p) where p is your ggplot object.

Section 5: Interactive Maps with leaflet

What is leaflet?

Leaflet is a JavaScript mapping library, wrapped for R. Unlike ggplot (which produces a static image), leaflet produces an interactive web map where users can zoom, pan, and click on features. It loads real map tiles (like Google Maps) as the background.

The build order (always the same)

leaflet()          |>   # 1. Create the widget (optionally pass a data frame)
  addTiles()       |>   # 2. Add a background map (default: OpenStreetMap)
  addMarkers(...)  |>   # 3. Add your data as a layer
  setView(...)          # 4. Set the starting view (optional)

Background map tile options

addTiles()                                     # Default: OpenStreetMap (street map)
addProviderTiles("CartoDB.Positron")           # Clean, minimal, light gray
addProviderTiles("Esri.WorldImagery")          # Satellite imagery
addProviderTiles("Esri.WorldTopoMap")          # Terrain map with elevation
addProviderTiles("NASAGIBS.ViirsEarthAtNight2012")  # Earth at night (lights)

The tilde ~ syntax — critical!

In leaflet, you reference data columns using ~column_name. The tilde ~ tells leaflet “look up this column from the data.” Without it, leaflet treats the value as a constant.

# Data frame version: pass data to leaflet(), use ~ to reference columns
storms75 |>
  leaflet() |>
  addTiles() |>
  addCircles(
    lng = ~long,        # ~ means: use the "long" column from the data
    lat = ~lat,         # ~ means: use the "lat" column from the data
    label = ~name,      # tooltip label: the "name" column
    radius = 50000,     # constant (no ~) — same radius for all circles, in meters
    fillOpacity = 0.7)

Types of markers/layers you can add

# Pin-style markers (for small numbers of points)
addMarkers(lng = ~lng, lat = ~lat, popup = "Fixed text")

# Small colored circles (for many points)
addCircleMarkers(lng = ~long, lat = ~lat,
                 radius = 5,          # size in pixels (constant)
                 color = "blue",
                 stroke = FALSE,      # no border around circle
                 fillOpacity = 0.7,
                 popup = ~as.character(datetime))  # click to see value

# Circles scaled by a variable (like hurricane wind radius)
addCircles(lng = ~long, lat = ~lat,
           radius = ~wind * 1000)     # radius in meters, scaled by wind column

# Polygons (for sf objects like fire perimeters, country borders)
addPolygons(fillColor = "red",
            fillOpacity = 0.5,
            weight = 1,              # border line thickness
            label = ~FIRE_NAME)      # hover label

Color-coding markers by a variable

In ggplot you’d write aes(color = variable). In leaflet, you can’t do that directly. Instead, you create a color palette function first, then call it with the column name.

# For a CATEGORICAL variable (like storm names, states)
pal <- colorFactor(palette = "viridis", domain = storms75$name)
# colorFactor assigns one distinct color per category
# domain tells it what all the possible values are

# For a CONTINUOUS variable (like temperature, income)
pal <- colorNumeric(palette = "Blues", domain = data$value)

# For BINNED ranges of a continuous variable
pal <- colorBin(palette = "RdYlGn", domain = data$value)

# Use the palette function inside addCircles or addPolygons:
addCircles(color = ~pal(name))   # pal(name) = "what color should 'Hurricane Allen' be?"
# NOT: color = ~name  ← this does NOT work

Adding a legend

addLegend(
  position = "bottomright",  # or "bottomleft", "topleft", "topright"
  pal = pal,                 # same palette function you used for colors
  values = ~name,            # column whose values determine the colors
  title = "Storm")

Setting the initial view

setView(
  lng = -122.26,   # longitude of center
  lat = 37.87,     # latitude of center
  zoom = 15)       # zoom level: 1=world, 5=country, 10=city, 15=neighborhood, 18=building

Displaying sf polygon data in leaflet

# CRITICAL: Must convert to WGS84 first!
cal_perims |>
  st_transform(crs = 4326) |>           # convert from whatever CRS it is to WGS84
  leaflet() |>
  addProviderTiles("Esri.WorldTopoMap") |>
  addPolygons(
    color = "red",
    fillOpacity = 0.5,
    weight = 1,
    label = ~FIRE_NAME)                 # hover over a polygon to see the fire name

HTML in popups (for richer click-to-see info)

# Popups appear when you CLICK on a marker/polygon
popup = ~paste0("<b>", name, "</b><br>Category: ", category)
# <b>...</b> = bold text
# <br> = line break
# You can use basic HTML tags inside popup text

Sample Quiz Questions — Leaflet

Q1: What is wrong with this code?

leaflet(storms) |> addTiles() |> addCircles(color = ~name)

A: You can’t directly map a column to color in leaflet using ~column_name. You need to first create a color palette function with colorFactor() (or similar), then use color = ~pal(name).

Q2: What does the zoom level of 1 show vs. zoom level 15 in leaflet’s setView()?

A: Zoom 1 shows the entire world. Zoom 15 shows a neighborhood-level view.

Q3: You have fire perimeter data loaded as an sf object in NAD83 projection. When you try to display it in leaflet, it doesn’t show up correctly. What is the fix?

A: Call st_transform(crs = 4326) before passing it to leaflet. Leaflet only accepts WGS84 (EPSG:4326) coordinates.

Q4: What is the difference between addMarkers(), addCircleMarkers(), and addCircles() in leaflet?

A: addMarkers() uses pin icons, good for a small number of labeled points. addCircleMarkers() uses small circles of fixed pixel size, good for many points. addCircles() uses circles whose radius is in real-world meters, so they can be scaled by a data variable (e.g., hurricane wind speed).

Q5: True or False: In leaflet, you reference a data column for the label argument by writing label = name.

A: False. You need the tilde: label = ~name.

Section 6: Raster Data with terra

What is raster data?

A raster is a grid of equally-sized cells, like pixels in an image. Each cell covers a geographic area and has one value (temperature, elevation, rainfall, vegetation index, etc.). It’s the right format for continuous data that changes smoothly across space.

NetCDF (.nc files) is a common raster format used for climate data. A NetCDF file can contain many layers — think of it like a stack of raster grids, one per time step.

Loading and exploring raster data

library(terra)

dat <- rast("nclimgrid_tavg.nc")
# rast() is the terra function to read raster files
# "tavg" = average temperature

dat
# Shows you:
# - dimensions: number of rows, columns, layers
# - resolution: size of each cell in degrees
# - extent: geographic bounding box (min/max lat/lon)
# - CRS: coordinate reference system
# - layer names and time values

Selecting a specific layer (time step)

dat[[1]]       # First layer — e.g., January 1895
dat[[1564]]    # Layer number 1564

How to calculate which layer corresponds to a date:

layer = (year - start_year) * 12 + month_number

Example: April 2025, data starts in 1895:
layer = (2025 - 1895) * 12 + 4 = 130 * 12 + 4 = 1564

Plotting raster data

# Quick plot (base R)
plot(dat[[1564]])                         # grayscale by default
plot(dat[[1564]], col = viridis(n = 100)) # viridis color palette, 100 color steps

# Convert Celsius to Fahrenheit directly in the plot
plot(dat[[1564]] * (9/5) + 32)
# You can do math on a raster object and it applies to every cell

Converting raster to data frame for ggplot

apr_2025 <- as.data.frame(dat[[1564]], xy = TRUE)
# as.data.frame converts the raster grid to one row per cell
# xy = TRUE adds x (longitude) and y (latitude) columns
# Result: a regular data frame with columns x, y, and the value column (e.g., tavg_1564)

Plotting raster with ggplot

ggplot() +
  geom_tile(data = apr_2025, aes(x = x, y = y, fill = tavg_1564)) +
  scale_fill_viridis_c()
# geom_tile draws a colored rectangle at each (x, y) location
# Use geom_tile NOT geom_raster (geom_raster can warn about uneven spacing)

Overlaying state borders on top of a raster

us_states <- ne_states(country = "United States of America", returnclass = "sf")

ggplot() +
  geom_tile(data = apr_2025, aes(x = x, y = y, fill = tavg_1564)) +  # raster first
  scale_fill_viridis_b(breaks = seq(-10, 25, by = 5)) +
  geom_sf(data = us_states, fill = "#FFFFFF00", color = "white") +    # state borders on top
  # fill = "#FFFFFF00" means: white color but 00 alpha = fully transparent (see-through)
  coord_sf(xlim = c(-124.7, -67), ylim = c(24.5, 49.4))             # zoom to contiguous US

Sample Quiz Questions — Raster

Q1: A NetCDF file contains monthly average temperature data from January 1895 through today. Which layer contains data for July 2000?

A: layer = (2000 - 1895) * 12 + 7 = 105 * 12 + 7 = 1267. So dat[[1267]].

Q2: Why should you use geom_tile() instead of geom_raster() to plot raster data in ggplot?

A: geom_raster() can produce a warning about “uneven horizontal intervals” in geographic data. geom_tile() handles this correctly.

Q3: What does as.data.frame(dat[[1]], xy = TRUE) return?

A: A regular data frame with one row per raster cell, with columns x (longitude), y (latitude), and a column for the cell value. This converts the raster format into something ggplot can use.

TEXT ANALYSIS

The Big Picture

Text analysis is about extracting meaning and statistics from text data. The typical workflow is:

raw text
→ tibble (wrap in a data frame)
→ tokenize (break into words)
→ remove stop words (remove "the", "a", "and", etc.)
→ count frequencies
→ [optional] TF-IDF (find distinctive words)
→ [optional] join with sentiment lexicon (attach emotion labels)
→ summarize by chapter/section/episode
→ visualize

Section 7: Getting Text Into R and Tokenizing

What is tokenization?

Tokenization means breaking a long piece of text into individual units called tokens. Usually, a token is one word. The result is a table where each row contains one token.

Loading text

# Option A: direct URL read
pp_raw <- readLines("https://www.gutenberg.org/cache/epub/1342/pg1342.txt")

# Option B: from janeaustenr package (simplest for Pride and Prejudice)
library(janeaustenr)
prideprejudice   # already a character vector, one element per line of the book

ALWAYS wrap text in a tibble first

# unnest_tokens() REQUIRES a data frame — a raw character vector won't work
pride_tbl <- tibble(text = prideprejudice)
# Now it's a data frame with one column "text" and one row per line

Tokenizing with unnest_tokens()

library(tidytext)

pride_tokens <- unnest_tokens(
  tbl    = pride_tbl,  # the data frame containing text
  input  = text,       # the column name that has the raw text
  output = word)       # the name of the new column for individual tokens

# Output: a data frame with ONE ROW PER WORD
# Example:
# word
# pride
# and
# prejudice
# by
# ...

# unnest_tokens automatically:
# - splits on spaces and punctuation
# - lowercases everything ("The" → "the")
# - strips punctuation ("don't" → "dont" or splits into tokens)

Bigrams (two-word pairs)

pride_bigrams <- unnest_tokens(
  tbl    = pride_tbl,
  input  = text,
  output = bigram,
  token  = "ngrams",  # instead of the default "words"
  n = 2)              # n = 2 means pairs of consecutive words

# Output rows look like:
# bigram
# it is
# is a
# a truth

# IMPORTANT: When a line of text ends, you can't form a bigram across lines
# This creates NA values — always filter them:
pride_bigrams <- pride_bigrams |> filter(!is.na(bigram))

Sample Quiz Questions — Tokenization

Q1: You have a character vector my_text. What is the first step before you can use unnest_tokens() on it?

A: Wrap it in a tibble: my_tbl <- tibble(text = my_text). unnest_tokens() requires a data frame.

Q2: What does unnest_tokens() do to the case of text?

A: It automatically converts everything to lowercase. “Hello” and “hello” both become “hello”.

Q3: What does token = "ngrams", n = 2 do in unnest_tokens()?

A: It tokenizes into bigrams — consecutive two-word pairs — instead of individual words.

Section 8: Stop Words and Frequency Analysis

What are stop words?

Stop words are extremely common words that carry no meaningful information on their own — “the”, “a”, “and”, “is”, “of”, “to”, etc. When analyzing text for meaning or interesting patterns, you typically want to remove these first.

stop_words
# A built-in tibble with 1,149 rows and 2 columns: word, lexicon
# Includes three lists: "SMART", "snowball", "onix"

Removing stop words with anti_join

anti_join(A, B, by = "col") keeps only rows in A that do NOT have a match in B.

# Before: pride_tokens has every word including "the", "a", "and"
# After: only meaningful content words remain
pride_tokens <- anti_join(pride_tokens, stop_words, by = "word")

Your token column MUST be named word for this to work, because stop_words has a column called word. This is why unnest_tokens() uses output = word by convention.

Removing stop words from bigrams (trickier!)

You can’t anti_join bigrams directly against stop_words, because stop_words contains single words, not two-word phrases. Instead:

# Split the bigram into two separate word columns, then filter each
pride_bigrams_clean <- pride_bigrams |>
  mutate(word1 = str_extract(bigram, "^\\w+"),    # extract first word
         word2 = str_extract(bigram, "\\w+$")) |>  # extract last word
  filter(!(word1 %in% stop_words$word),            # remove if first word is a stop word
         !(word2 %in% stop_words$word))             # remove if second word is a stop word

TF-IDF — finding distinctive words

TF-IDF = Term Frequency × Inverse Document Frequency. It’s a score that is HIGH when a word appears frequently in one particular document but rarely across all documents. Used to find words that characterize/distinguish one group from others.

Example: if “dragons” appears a lot in Season 1 of Game of Thrones but rarely in other seasons, it gets a high TF-IDF for Season 1.

tfidf_data <- got_tokens |>
  count(Season, word, sort = TRUE) |>   # count words per season
  bind_tf_idf(
    term     = word,    # which column has the tokens
    document = Season,  # which column defines the "document" (here: season = document)
    n        = n) |>    # which column has the counts
  group_by(Season) |>
  top_n(8, tf_idf) |>  # top 8 most distinctive words per season
  ungroup()

Sample Quiz Questions — Stop Words and Frequency

Q1: What does anti_join(tokens, stop_words, by = "word") do?

A: It removes all rows from tokens where the word appears in stop_words. Only non-stop-word tokens remain.

Q2: Why can’t you do anti_join(bigrams, stop_words, by = c("bigram" = "word")) to remove stop words from bigrams?

A: Because stop_words contains single words, and bigram is a two-word string like “in the”. The full bigram string will never match any single word. You have to split the bigram into word1 and word2 and filter each separately.

Q3: A word has a high TF-IDF score for Season 3 of a show. What does this mean?

A: The word appears frequently in Season 3 but rarely across all other seasons. It is a distinctive word for Season 3.

Section 9: Sentiment Analysis

What is sentiment analysis?

Sentiment analysis assigns emotional meaning to words. The idea: some words are inherently positive (“joy”, “love”, “excellent”), others are inherently negative (“misery”, “hate”, “terrible”). By counting how many positive vs. negative words appear in a text, you can estimate the overall emotional tone.

A sentiment lexicon is just a table that maps words to their sentiment labels or scores.

The four lexicons

Lexicon What it provides
"bing" Each word is labeled “positive” or “negative”
"afinn" Each word gets an integer score from -5 (very negative) to +5 (very positive)
"nrc" Each word is tagged with one or more emotions: positive, negative, anger, joy, fear, sadness, surprise, trust, anticipation, disgust
"loughran" Financial sentiment (positive, negative, litigious, uncertain, etc.) 
# Load as CSV (required for rendering in .qmd files — the interactive version fails)
bing <- read_csv("bing.csv")
nrc  <- read_csv("nrc.csv")

# The bing lexicon looks like:
# word       sentiment
# abandon    negative
# abundance  positive
# ...

# The nrc lexicon maps ONE WORD to MULTIPLE ROWS
nrc |> filter(word == "abandon")
# word     sentiment
# abandon  fear
# abandon  negative
# abandon  sadness
# One word can carry multiple emotion tags simultaneously

Joining tokens with a sentiment lexicon

# Use inner_join because you ONLY want words that appear in the lexicon
# (left_join would keep all words and give NA for ones with no sentiment)
sentiment_words <- inner_join(pride_tokens, bing, by = "word")
# Result: only the tokens that have a known sentiment are kept
# Each row now has both the word and its sentiment label

Why inner_join not left_join?

  • inner_join: keeps only rows that have a match in both tables → only words with known sentiments
  • left_join: keeps all rows from the left table → words without sentiments get NA

For sentiment analysis you want inner_join. You’re not interested in neutral words.

Counting and plotting sentiment words

sentiment_words |>
  count(word, sentiment, name = "count", sort = TRUE) |>
  filter(word != "miss") |>    # "miss" is coded negative but usually means "Miss Bennet"
  slice_head(n = 20) |>
  ggplot(aes(x = count,
             y = reorder(word, count),
             fill = sentiment)) +   # color bars by positive/negative
  geom_col()

Sentiment score by chapter

The goal: track how the emotional tone changes across chapters.

# Step 1: collapse the entire text into one string, then split by "Chapter N"
pride_collapsed <- paste(prideprejudice, collapse = " ")
# paste(..., collapse = " ") joins all lines into one long string

pride_split <- str_split(pride_collapsed, pattern = "Chapter\\s\\d+")
# str_split splits the string wherever "Chapter" followed by whitespace and digits appears
# Returns a LIST (not a vector)

pride_chapters <- pride_split[[1]][-1]
# [[1]] extracts the vector from the list (str_split always returns a list)
# [-1] drops the first element (it's the title page, before Chapter 1)

# Step 2: make a data frame
pride_chaps <- tibble(
  text    = pride_chapters,    # one element per chapter
  chapter = 1:length(pride_chapters))

# Step 3: tokenize and join sentiment
pride_toks <- unnest_tokens(pride_chaps, input = text, output = word)
pride_sent <- inner_join(pride_toks, bing, by = "word") |>
  filter(word != "miss")

# Step 4: compute score per chapter = (# positive words) - (# negative words)
chapter_scores <- pride_sent |>
  count(chapter, sentiment) |>          # count positive and negative per chapter
  pivot_wider(
    names_from  = sentiment,            # spread sentiment labels into columns
    values_from = n,
    values_fill = 0) |>                 # if a chapter has no negative words, use 0 not NA
  mutate(score = positive - negative)   # score = positives minus negatives

# Step 5: plot
chapter_scores |>
  mutate(pos_neg = if_else(score >= 0, "positive", "negative")) |>
  ggplot(aes(x = chapter, y = score, fill = pos_neg)) +
  geom_col()

Sentiment by fixed-size sections (not chapters)

Instead of splitting by chapter headings, divide the whole book into blocks of 80 lines using integer division.

section_scores <- tibble(text = prideprejudice) |>
  filter(!str_detect(text, "^Chapter\\s\\d+"),  # remove chapter heading lines
         text != "") |>                           # remove blank lines
  mutate(
    line_number = row_number(),           # assign a sequential line number
    section     = line_number %/% 80) |>  # integer divide: lines 1-79 → section 0, 80-159 → section 1, etc.
  unnest_tokens(input = text, output = word) |>
  inner_join(bing, by = "word") |>
  count(section, sentiment) |>
  pivot_wider(names_from = sentiment, values_from = n, values_fill = 0) |>
  mutate(score = positive - negative)

%/% is integer division: 81 %/% 80 = 1, 160 %/% 80 = 2. All lines in the same 80-line block get the same section number. This is how you create uniform-size text windows.

Sample Quiz Questions — Sentiment Analysis

Q1: What is the difference between the bing and NRC lexicons?

A: Bing labels each word as either “positive” or “negative” (binary). NRC assigns one or more emotion categories (joy, fear, anger, sadness, etc.) to each word — one word can map to multiple rows.

Q2: You run inner_join(my_tokens, bing, by = "word"). Some words from your text are NOT in the bing lexicon. What happens to them?

A: They are dropped. inner_join only keeps rows that have a match in both tables. Words not in the lexicon simply don’t appear in the output.

Q3: After joining tokens with bing sentiment, you want to compute a sentiment score per chapter as (positives - negatives). You use pivot_wider(names_from = sentiment, values_from = n). Why should you add values_fill = 0?

A: Some chapters might have no negative (or no positive) words, which would create NA in that cell. values_fill = 0 ensures those become 0, so the subtraction positive - negative works correctly.

Q4: What does %/% do? Give an example.

A: %/% is integer division — it divides and drops the remainder. 81 %/% 80 = 1, 160 %/% 80 = 2. It’s used to assign all lines within a fixed-size window (e.g., every 80 lines) to the same section number.

Q5: Why do you need to filter out the word “miss” in Pride and Prejudice sentiment analysis?

A: The bing lexicon classifies “miss” as negative (as in “to miss something/someone”), but in Pride and Prejudice it almost always appears as a title (“Miss Bennet”, “Miss Darcy”). Keeping it would incorrectly add negative sentiment throughout the book.

Server-side: reactive data filtering + rendering a leaflet map

#| context: server

# 1. Create a reactive expression: a filtered version of the data
#    This re-runs automatically whenever the user changes an input
filtered_data <- reactive({
  crashes |>
    filter(county == input$county_select,           # input$county_select reads the dropdown
           date >= input$date_range[1],             # date_range[1] = start date
           date <= input$date_range[2])             # date_range[2] = end date
})

# 2. Render the leaflet map
output$map <- renderLeaflet({
  data <- filtered_data()    # call the reactive with () to get its current value

  leaflet(data = data) |>
    addProviderTiles("CartoDB.Positron") |>
    addCircleMarkers(
      lng = ~longitude, lat = ~latitude,
      radius = 5,
      color = ~pal(COLLISION_SEVERITY),  # color mapped via palette function
      stroke = FALSE,
      fillOpacity = 0.7,
      popup = ~paste0("<b>", LOCATION, "</b><br>Severity: ", COLLISION_SEVERITY)) |>
    addLegend(pal = pal, values = ~COLLISION_SEVERITY, position = "bottomright")
})

UI side: displaying the leaflet map output

# In the UI chunk (or sidebar/main panel), declare where the map goes
leafletOutput("map")     # "map" must match the name in output$map above

Key Shiny rules to remember

  • Access user input values with input$widget_id (where widget_id is what you gave in selectInput(), etc.)
  • Access reactive expression values by calling them with (): filtered_data() not filtered_data
  • renderLeaflet({...}) and leafletOutput("id") always come in pairs
  • A reactive({}) expression re-runs whenever any input$... it uses changes

Sample Quiz Questions — Shiny + Leaflet

Q1: In a Shiny dashboard, you have a reactive expression filtered_data <- reactive({...}). Inside renderLeaflet({}), how do you access its current value?

A: By calling it with parentheses: filtered_data(). Without the (), you’d get the reactive expression object itself, not the data.

Q2: What must be true about the string ID used in renderLeaflet() and leafletOutput()?

A: They must match exactly. If you write output$my_map <- renderLeaflet({...}), then the UI must have leafletOutput("my_map").

Q3: In what code chunk context does reactive({}) belong?

A: In a chunk with #| context: server. Reactive code belongs in the server context.

Q5: True or False: A word like “storm” that appears in the NRC lexicon will appear in exactly one row of the NRC table.

Q6: You want to color circles in leaflet by a categorical variable category in your data. What two steps are required?

A: (1) Create a palette function: pal <- colorFactor(palette = "viridis", domain = data$category). (2) Use it in addCircles() or addCircleMarkers() with color = ~pal(category).

Q7: What does st_drop_geometry() do, and when would you use it?

A: It removes the geometry column from an sf object, returning a plain data frame. You’d use it when doing data analysis (EDA, counting, summarizing) where you don’t need the spatial component, because carrying the geometry column slows down dplyr operations unnecessarily.
