1. Dates and Times

A. Core date/time object types

1. POSIXct = date-time (stores both date and time)

  • Internally built on top of a double
  • Represents Unix time (seconds since Jan 1, 1970 UTC)
now <- Sys.time()
now
class(now)
typeof(now)
unclass(now)

Expected:

  • class(now) → "POSIXct" "POSIXt"
  • typeof(now) → "double"

2. Date = date only

halloween <- as.Date("2000-10-31")
class(halloween)
typeof(halloween)

Expected:

  • class(halloween) → "Date"
  • typeof(halloween) → "double"

B. Unix Time

Definition: number of seconds elapsed since midnight UTC on Jan 1, 1970.

  • 0 = "1970-01-01 00:00:00 UTC"
  • 60 = "1970-01-01 00:01:00 UTC"
  1. Unix timestamp → datetime: as.POSIXct(x = 60, tz = "UTC")
  2. Datetime → unix timestamp: unclass(Sys.time())

C. Creating datetimes

  1. From numeric Unix time: as.POSIXct(x = 60, tz = "UTC")
  2. From standard string: as.POSIXct(x = "1970-01-01 00:01:00", tz = "UTC")
  3. From custom formatted string: as.POSIXct(x = "Jan 1, 1970 12:01 am", format = "%b %d, %Y %I:%M %p", tz = "UTC")

D. Creating dates

  1. Simple ISO format: as.Date("2000-10-31")
  2. Custom formats
as.Date("03-16-2026", format = "%m-%d-%Y")
as.Date("2026-March-16", format = "%Y-%B-%d")
as.Date("2026-Mar-16", format = "%Y-%b-%d")

E. Creating dates/times with lubridate

Common parser functions

Pattern names tell you the order:

  • ymd() = year-month-day
  • mdy() = month-day-year
  • dmy() = day-month-year
  • Add time parts:
    • ymd_hms()
    • mdy_hm()
    • dmy_hm()

Examples

library(tidyverse)  # contains lubridate

mdy_hm("Jan 1, 1970 12:01 am")
dmy_hm("1-1-1970 12:01")
ymd("2026-04-09")
ymd_hms("2026-03-08 01:00:00", tz = "America/Los_Angeles")
today() # returns a `Date` object

2) Time Spans & Timezones

Base R subtraction → difftime

a <- today()
b <- ymd("1941-09-27")
a - b
class(a - b)
  • Subtracting two Dates gives a difftime
  • difftime can have inconsistent units

duration = fixed number of seconds

Convert difftime → duration

oski_age_sec <- as.duration(a - b)

Constructors

dseconds(15)
dminutes(10)
dhours(c(12, 24))
ddays(0:3)
dweeks(3)
dyears(1)

Key idea:

  • duration = fixed seconds
  • A “day” here = 86400 seconds
  • A “year” is an average number of seconds (not always calendar-exact)

period = human calendar time (DST / leap-aware)

Constructors

seconds(15)
minutes(10)
hours(c(12, 24))
days(0:3)
weeks(3)
years(1)

Key idea:

  • period tracks human units
  • It adapts to irregularities like:
    • daylight savings
    • leap years

D. interval = specific start + end points

date1 <- ymd("1941-09-27")
date2 <- ymd("2026-03-18")

interval(date1, date2)
int_length(interval(date1, date2))
interval(date1, date2) / years(1)
interval(date1, date2) / months(1)
interval(date1, date2) / weeks(1)

Key idea:

  • interval is tied to real points on the timeline
  • Useful for “how many years/months/weeks between two dates?”

E. Key Differences (duration vs period)

Daylight Savings Time

one_am <- ymd_hms("2026-03-08 01:00:00", tz = "America/Los_Angeles")
  • Add fixed 1 day duration
one_am + ddays(1)
# "2026-03-09 02:00:00 PDT"
  • Add calendar 1 day period
one_am + days(1)
# "2026-03-09 01:00:00 PDT"

Why?

  • DST spring-forward makes that calendar day only 23 hours long
  • ddays(1) = exact 86400 seconds
  • days(1) = “same clock time tomorrow”

Leap year

ymd("2024-01-01") + dyears(1)
# "2024-12-31 06:00:00 UTC"

ymd("2024-01-01") + years(1)
# "2025-01-01"

Interpretation:

  • dyears(1) = average fixed seconds
  • years(1) = true calendar year

F. Timezones

  1. Current system timezone: Sys.timezone()
  2. Use a timezone when parsing
ymd_hms("2026-03-08 01:00:00", tz = "America/Los_Angeles")
as.POSIXct("1970-01-01 00:01:00", tz = "UTC")
  1. OlsonNames() like “America/Los_Angeles”, “America/New_York”, “UTC”.

G. Dashboard Example

Convert a character datetime column to datetime. The slide’s CreateDatetime starts as character:

cfs |> select(CreateDatetime) |> slice_head(n = 4)

Then convert:

cfs <- mutate(cfs, CreateDatetime = as_datetime(CreateDatetime))

If they ask: “Convert a string timestamp column into datetime type” → this is the syntax.

E. Server Logic

The 3 rules to write the server

  1. Save displayed objects to output$...
  2. Build displayed objects with render*()
  3. Access input values with input$...

Canonical example

output$plot <- renderPlot({
  ggplot(data = faithful, aes(x = waiting)) +
    geom_histogram(
      bins = input$bins,
      color = "white"
    ) +
    theme_minimal()
})

F. Reactivity

If you use an input inside a render*() block:

output$plot <- renderPlot({
  ggplot(data = faithful, aes(x = waiting)) +
    geom_histogram(bins = input$bins, color = "white") +
    theme_minimal()
})

Then:

  • input$bins changes
  • output$plot automatically re-renders

Reactive values can only be used in reactive contexts. For example, this is OK:

output$plot <- renderPlot({
  ggplot(data = faithful, aes(x = waiting)) +
    geom_histogram(bins = input$bins, color = "white") +
    theme_minimal()
})

But, this is NOT OK:

num_bins <- input$bins

output$plot <- renderPlot({
  ggplot(data = faithful, aes(x = waiting)) +
    geom_histogram(bins = num_bins, color = "white") +
    theme_minimal()
})

Why wrong?

  • input$bins is reactive
  • You cannot grab it outside a reactive context like that

We can also define your own reactive variable

num_bins <- reactive({
  input$bins
})

output$plot <- renderPlot({
  ggplot(data = faithful, aes(x = waiting)) +
    geom_histogram(bins = num_bins(), color = "white") +
    theme_minimal()
})

VERY IMPORTANT:

  • Reactive objects are functions
  • So you must call them with ():
    • num_bins() not num_bins

H. Avoid Redundant Code with reactive()

  • Bad / repetitive version: You filter penguins separately in both outputs.
  • Better version with reactive object
penguins_filtered <- reactive({
  penguins |>
    filter(body_mass_g >= input$mass[1],
           body_mass_g <= input$mass[2])
})
  • Then use it:
output$plot <- renderPlot({
  gg <- ggplot(data = penguins_filtered(),
               aes(x = bill_depth_mm, fill = species)) +
    theme_minimal()

  if (input$graphic == "density") {
    gg + geom_density(alpha = 0.7)
  } else {
    gg + geom_boxplot(aes(y = species))
  }
})

output$table <- renderTable({
  penguins_filtered() |>
    group_by(species) |>
    summarize(
      median = median(bill_depth_mm),
      IQR = IQR(bill_depth_mm),
      mean = mean(bill_depth_mm),
      sd = sd(bill_depth_mm)
    )
})

Exam takeaway: if the same transformed data is used in multiple outputs, wrap it in reactive({...}).

J. .data[[ ]]

Problem: passing a column name as a string fails

my_summary <- function(df, col_name) {
  df |> summarize(avg = mean(col_name))
}

my_summary(mtcars, "mpg")

This gives bad output (NA) because "mpg" is just a string, not the column itself.

Solution: use .data[[ ]]

my_summary <- function(df, col_name) {
  df |> summarize(avg = mean(.data[[col_name]]))
}

my_summary(mtcars, "mpg")

Rule to memorize:

  • If the column name is stored as a string or comes from input$..., use:
    .data[[col_name]]
    or
    .data[[input$variable]]

Wrong

variable <- "bill_length_mm"

ggplot(data = penguins, aes(x = variable, fill = species)) +
  geom_density(alpha = 0.7)

This treats variable as the literal string, not the column.

Correct

variable <- "bill_length_mm"

ggplot(data = penguins, aes(x = .data[[variable]], fill = species)) +
  geom_density(alpha = 0.7)

Or inside Shiny:

ggplot(data = penguins,
       aes(x = .data[[input$variable]], fill = species)) +
  geom_density(alpha = 0.7)

This is the table version of the same idea.

output$table <- renderTable({
  penguins |>
    group_by(species) |>
    summarize(
      median = median(.data[[input$variable]], na.rm = TRUE),
      IQR = IQR(.data[[input$variable]], na.rm = TRUE),
      mean = mean(.data[[input$variable]], na.rm = TRUE),
      sd = sd(.data[[input$variable]], na.rm = TRUE)
    )
})

Common Traps

Dates & times

  • Date ≠ POSIXct
  • dyears(1) ≠ years(1)
  • ddays(1) ≠ days(1)
  • wday(x) numeric vs wday(x, label = TRUE) labeled factor
  • as.Date() for date only
  • as.POSIXct() / ymd_hms() for date-time

Shiny

  • input$... is reactive
  • Don’t use input$... outside reactive contexts unless wrapped in reactive({...})
  • Reactive objects must be called with ()
    • filtered_df() not filtered_df
  • UI output function must match render function
  • Dynamic column names in tidyverse/ggplot:
    • use .data[[input$variable]]
    • NOT aes(x = input$variable)
