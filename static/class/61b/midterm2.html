Asymptotics

Order of Growth

  • Ignore Low-Order Terms: As N becomes very large, terms with smaller exponents become negligible. For example, in 3N3+N23N^3 + N^23N3+N2, the N2N^2N2 is ignored.
  • Ignore Multiplicative Constants: Constants do not change the fundamental growth rate. For example, 8N8N8N grows in the same way as NNN.

Code Example (Linear Growth):

public static void countEvens(int[] numbers) {
    int evens = 0;
    for (int i = 0; i < numbers.length; i++) { // Loop runs N times
        if (numbers[i] % 2 == 0) {
            evens += 1;
        }
    }
    System.out.println("Number of evens: " + evens);
}
  • Analysis: Because the loop runs once for every element in the array, the order of growth is N (linear).

Code Example (Quadratic Growth):

public static void countDuplicates(int[] a) {
    int duplicates = 0;
    for (int i = 0; i < a.length; i++) {
        for (int j = i + 1; j < a.length; j++) { // Nested loop
            if (a[i] == a[j]) {
                duplicates += 1;
            }
        }
    }
}
  • Analysis: The number of comparisons is roughly N22\frac{N^2}{2}2N2​, so the order of growth is N2N^2N2.

Asymptotic Analysis of Loops

There is no “magic shortcut” for analysis; it requires identifying a cost model (a representative operation to count) and observing how that count changes with input NNN.

Example: Nested Loops (Quadratic)

When the inner loop depends on the outer loop’s index, the total work is often the sum of an arithmetic progression.

for (int i = 0; i < a.length; i++) {
    for (int j = i + 1; j < a.length; j++) {
        if (a[i] == a[j]) { duplicates += 1; }
    }
}
  • Analysis: The number of checks is (N−1)+(N−2)+⋯+1=N(N−1)2(N-1) + (N-2) + \dots + 1 = \frac{N(N-1)}{2}(N−1)+(N−2)+⋯+1=2N(N−1)​
  • Order of Growth: Θ(N2)\Theta(N^2)Θ(N2).

Example: Geometric Growth (Linear)

This “trickier” example features an outer loop that doubles and an inner loop that scales with the outer index.

for (int i = 1; i <= N; i = i * 2) {
    for (int j = 0; j < i; j += 1) {
        System.out.println("hello");
    }
}
  • Analysis: If NNN is a power of 2, the total calls are 1+2+4+8+⋯+N1 + 2 + 4 + 8 + \dots + N1+2+4+8+⋯+N.
  • Mathematical Fact: The sum of powers of 2 up to NNN is 2N−12N - 12N−1.
  • Order of Growth: Θ(N)\Theta(N)Θ(N). Despite the nested appearance, it is linear, similar to the behavior of ArrayList resizing.

Recursive Runtime Analysis

Exponential Growth (The “Double Work” Pattern)

When a function calls itself twice for each decrement of NNN, the work doubles at every level of the recursion tree.

  • Definition: Each increase in NNN by 1 results in twice as many total calls.
  • Example (Toy Recursion):
    public static int f3(int n) {
    if (n <= 1) return 1;
    return f3(n - 1) + f3(n - 1); // Two recursive calls
}
  • Analysis: The total number of calls follows the geometric sum 1+2+4+⋯+2N−11 + 2 + 4 + \dots + 2^{N-1}1+2+4+⋯+2N−1, which simplifies to 2N−12^N - 12N−1.
  • Order of Growth: Θ(2N)\Theta(2^N)Θ(2N).

Logarithmic Growth (Binary Search)

Binary search is highly efficient because it repeatedly halves the search space.

  • Definition: The problem size NNN is divided by 2 until it reaches 1. The number of steps required is the number of times you can divide NNN by 2, which is log⁡2N\log_2 Nlog2​N.
  • Example Syntax:
    static int binarySearch(String[] sorted, String x, int lo, int hi) {
    if (lo > hi) return -1;
    int m = (lo + hi) / 2;
    int cmp = x.compareTo(sorted[m]);
    if (cmp < 0) return binarySearch(sorted, x, lo, m - 1);
    else if (cmp > 0) return binarySearch(sorted, x, m + 1, hi);
    else return m;
}
  • Order of Growth: Θ(log⁡N)\Theta(\log N)Θ(logN). In practice, this is nearly as fast as constant time (Θ(1)\Theta(1)Θ(1)), even for massive datasets.

Mergesort

Mergesort is a “divide and conquer” algorithm that is significantly faster than simpler sorts like Selection Sort (Θ(N2)\Theta(N^2)Θ(N2)).

  • The Merge Operation: Combining two sorted arrays of total size NNN into one sorted array takes Θ(N)\Theta(N)Θ(N) time because you must write every element into a new array exactly once.
  • The Strategy: 1. Split the array into two halves. 2. Recursively Mergesort both halves. 3. Merge the two sorted halves.
  • Overall Runtime: Because there are log⁡N\log NlogN levels of splitting and each level performs a total of NNN work during the merge phase, the total runtime is Θ(Nlog⁡N)\Theta(N \log N)Θ(NlogN).

Summation Formulas

  1. Arithmetic Sum: 1+2+3+⋯+Q=Q(Q+1)2=Θ(Q2)1 + 2 + 3 + \dots + Q = \frac{Q(Q+1)}{2} = \Theta(Q^2)1+2+3+⋯+Q=2Q(Q+1)​=Θ(Q2).
  2. Geometric Sum: 1+2+4+8+⋯+Q=2Q−1=Θ(Q)1 + 2 + 4 + 8 + \dots + Q = 2Q - 1 = \Theta(Q)1+2+4+8+⋯+Q=2Q−1=Θ(Q) (where QQQ is a power of 2).

Disjoint Sets

  • Disjoint Sets: A collection of elements partitioned into non-overlapping (disjoint) sets. Each element belongs to exactly one set.
  • Dynamic Connectivity Problem: The challenge of maintaining these sets as we add connections between elements and query whether two elements are in the same set.
  • Transitivity: If item A is connected to B, and B is connected to C, then A is connected to C.
  • The data structure supports two primary operations:
    • connect(int p, int q): Connects two items, ppp and qqq, potentially merging their respective sets.
    • isConnected(int p, int q): Returns true if ppp and qqq are in the same connected component.
public interface DisjointSets {
    void connect(int p, int q);     // Connects p and q
    boolean isConnected(int p, int q); // Returns true if connected
}

Implementations

Quick Find

  • Concept: Uses an array where the value at each index is an “ID” representing the set it belongs to.
  • isConnected: Very fast; simply checks if id[p] == id[q].
  • connect: Slow; must iterate through the entire array to update all IDs of one set to match the other.
  • Runtime: isConnected is Θ(1)\Theta(1)Θ(1), connect is Θ(N)\Theta(N)Θ(N).

Quick Union

  • Concept: Each element stores a reference to its “parent,” forming a tree structure. The “root” of the tree represents the set ID.
  • connect(p, q): Find the roots of ppp and qqq, then make one root the parent of the other.
  • Defect: Trees can become very tall (skinny), leading to poor performance.
  • Runtime: Both operations are O(N)O(N)O(N) in the worst case.

Weighted Quick Union (WQU)

  • Concept: Similar to Quick Union, but it always links the root of the smaller tree (by number of elements) to the root of the larger tree to keep the overall structure flat.
  • Improvement: This ensures that the maximum height of any tree is log⁡N\log NlogN.
  • Runtime: Both operations are O(log⁡N)O(\log N)O(logN).
    • Why Big O and not Θ\ThetaΘ? Because in some cases (like if the items are already connected), the operation might be much faster, such as constant time Θ(1)\Theta(1)Θ(1).

WQU with Path Compression

  • Concept: A “clever idea” where every time find or isConnected is called, all nodes visited on the path to the root are re-attached directly to the root.
  • Effect: This flattens the tree even further over time, making future operations nearly constant time.
  • Runtime: Performs MMM operations in approximately O(Mα(N))O(M \alpha(N))O(Mα(N)) time, where α\alphaα is the inverse Ackermann function (effectively constant for all practical values of NNN).

Binary Search Trees

A BST is a specialized tree structure used to implement Sets and Maps efficiently.

  • Formal Definition: A BST is a rooted binary tree where for every node X:
    • Every key in the left subtree is less than X’s key.
    • Every key in the right subtree is greater than X’s key.
  • Ordering: This property must hold for every node in the tree.

Key Operations

  • contains(key): Start at the root. If the search key is smaller than the current node, go left; if larger, go right. If equal, you found it!
  • insert(key): Similar to contains. Search for the key; when you reach a “null” spot where the key should have been, create a new node there.
  • delete(key):
    • 0 or 1 children: Simply move the child up to replace the deleted node.
    • 2 children (Hibbard Deletion): Find the “successor” (the smallest item in the right subtree), swap it with the node to be deleted, and then delete the successor from its original spot.

  • Balanced Tree: Height is proportional to log⁡N\log NlogN. Operations take Θ(log⁡N)\Theta(\log N)Θ(logN).
  • Spindly Tree: If items are inserted in sorted order, the tree becomes a long line. Height is proportional to NNN. Operations take Θ(N)\Theta(N)Θ(N).

B Trees (2-3 and 2-3-4 Trees)

The BST Performance Problem

The efficiency of a BST depends entirely on its height.

  • Bushy (Balanced) Tree: Height is Θ(log⁡N)\Theta(\log N)Θ(logN). Operations are fast.
  • Spindly Tree: If items are inserted in sorted order, the tree becomes a line with height Θ(N)\Theta(N)Θ(N). Operations become slow.
  • Crucial Distinction: Big O is not the same as “Worst Case.” A BST is always O(N)O(N)O(N), but we hope for Θ(log⁡N)\Theta(\log N)Θ(logN) average-case performance.

B-Trees ADT

A B-Tree avoids spindliness by allowing nodes to hold multiple items and by growing upwards rather than downwards.

  • Definition: A B-Tree of order LLL is a rooted tree where:
    • All leaves are at the same depth (perfect balance).
    • For any node, items are stored in sorted order. All items in a child’s subtree are bounded by the items in the parent node.
    • Non-leaf nodes with kkk items have exactly k+1k+1k+1 children.
    • 2-3 Tree: A B-Tree where each node can have 1 or 2 items (and 2 or 3 children).
    • 2-3-4 Tree: A B-Tree where each node can have 1, 2, or 3 items (and up to 4 children).

Core B-Tree Operations

A. Search (contains): The logic is similar to a BST but involves checking multiple items within a node.

  • If the key is less than the first item, go to the leftmost child.
  • If the key is between two items, go to the child between them.
  • If the key is greater than the last item, go to the rightmost child.

B. Insertion (add): B-Trees never add new leaf nodes at the bottom. Instead, they always add items to existing leaf nodes.

  1. Search for the appropriate leaf node.
  2. Add the item to that node.
  3. Splitting (The “Chain Reaction”): If a node becomes too full (exceeds LLL items), it “splits”:
    • The middle item is pushed up into the parent node.
    • The remaining items form two new separate nodes.
    • If the root splits, the middle item becomes a new root, increasing the height of the entire tree by one.

Left-Leaning Red-Black Trees

An LLRB is a BST that mimics a 2-3 tree by adding a “color” to its edges (links). In an LLRB, a “red” link represents a connection between two items that would be in the same node in a 2-3 tree.

Core Properties:

  1. 1-1 Correspondence: Every 2-3 tree has exactly one unique LLRB representation.
  2. Left-Leaning: Red links must lean to the left.
  3. No Consecutive Red Links: You cannot have two red links in a row.
  4. Black Balance: Every path from the root to a leaf has the same number of black links (this ensures the tree is never more than ~2x the height of a perfect B-Tree).

When inserting into an LLRB, we always insert with a red link. We then use three tools to restore the LLRB properties (left < root < right):

  1. Rotate Left: Used if we have a right-leaning red link. (Usually performed on a node G and its right child P. P becomes the new parent, and G becomes its left child.)
  2. Rotate Right: Used if we have two consecutive left-leaning red links. (The inverse; performed on a node G and its left child P. P becomes the new parent, and G becomes its right child.)
  3. Color Flip: Used if a node has two red children. This effectively “splits” a 2-3 tree node and sends the middle item up.

Syntax Example (Conceptual):

private Node put(Node h, Key key, Value val) {
    if (h == null) return new Node(key, val, RED);

    // BST insert logic
    int cmp = key.compareTo(h.key);
    if      (cmp < 0) h.left  = put(h.left,  key, val);
    else if (cmp > 0) h.right = put(h.right, key, val);
    else              h.val   = val;

    // LLRB insert logic
    if (isRed(h.right) && !isRed(h.left))      h = rotateLeft(h);
    if (isRed(h.left)  &&  isRed(h.left.left)) h = rotateRight(h);
    if (isRed(h.left)  &&  isRed(h.right))     flipColors(h);

    return h;
}

Heaps

The Priority Queue (Abstract Data Type)

A Priority Queue is a collection that allows you to track and remove either the smallest (MinPQ) or largest (MaxPQ) item efficiently. Unlike a standard Queue (FIFO), items are removed based on their “priority” value.

  • Primary Operations:
    • add(Item x): Puts an item into the PQ.
    • getSmallest(): Returns the item with the minimum value.
    • removeSmallest(): Removes and returns the item with the minimum value.

Example Usage:

MinPQ<Transaction> pq = new HeapMinPQ<>();
pq.add(new Transaction(100)); // Priority 100
pq.add(new Transaction(20));  // Priority 20
Transaction t = pq.removeSmallest(); // Returns the priority 20 transaction

The Binary Heap (Implementation)

A Binary Heap is the standard data structure used to implement a Priority Queue. To be a Min-Heap, it must satisfy two properties:

  1. Min-Heap Property: Every node is less than or equal to its children. This guarantees the root is always the smallest item.
  2. Complete Property: The tree is missing items only at the bottom level, and all nodes are as far left as possible. This ensures the tree is always “bushy” (balanced).

Core Operations (The “Swim” and “Sink” Logic)

  • add (Swim): Add the new item to the end of the heap (the next available leaf). To restore the heap property, compare it with its parent; if it’s smaller, swap them. Repeat until the parent is smaller or it reaches the root.
  • removeSmallest (Sink): Swap the root with the last item in the heap, then delete the last item. To restore the property, “sink” the new root by swapping it with its smallest child until it is smaller than both children.

Tree Representations

How to store a tree-like structure in memory:

  1. Recursive (Explicit) Nodes: Similar to a BST, where each node is an object with left and right pointers. This is intuitive but consumes more memory.
  2. Array-Based Representation (Standard): Because heaps are complete trees, they can be stored in an array without any “gaps.” This is highly memory-efficient. Mapping (if root is at index 1):
    • parent(k) = k / 2
    • leftChild(k) = k * 2
    • rightChild(k) = k * 2 + 1

Performance Summary

By using a Binary Heap, the PQ operations stay logarithmic because the height of a complete tree is always Θ(log⁡N)\Theta(\log N)Θ(logN).

Graphs & Traversals

  • Graph: A collection of vertices (nodes) connected by edges. A tree is actually a special type of graph that is connected and has no cycles.
  • Directed Graph: Edges have a direction (e.g., a one-way street or a Twitter “follow”).
  • Undirected Graph: Edges are bidirectional (e.g., a two-way street or a Facebook “friendship”).
  • Cyclic vs. Acyclic: A cyclic graph contains at least one cycle (a path that starts and ends at the same vertex). An acyclic graph has no cycles.
  • Path: A sequence of vertices connected by edges.

Tree Traversals

Before moving to general graphs, the lecture reviews how we visit nodes in a tree:

  • Preorder: Visit the root, then traverse subtrees. (Root, Left, Right)
  • Inorder: Traverse left subtree, visit root, then traverse right subtree. (Left, Root, Right) — Note: This visits nodes in alphabetical/numerical order in a BST.
  • Postorder: Traverse subtrees, then visit root. (Left, Right, Root)
  • Level Order (BFS): Visit nodes top-to-bottom, left-to-right by depth.

Graph Traversals

Graph traversal is more complex than tree traversal because graphs can have cycles (which could cause infinite loops) and may not be fully connected.

Depth First Search (DFS)

DFS is used to solve the “All Paths” problem: “Is there a path from source sss to every other vertex, and if so, what is it?”

  • Concept: Explore as deep as possible along a branch before backtracking. It uses a marked[] array to keep track of visited vertices to avoid cycles.
  • Path Tracking: To remember the actual path, we use an edgeTo[] array where edgeTo[w] = v means we reached node w from node v.
  • Analogy: Exploring a maze by following one path until you hit a dead end, then turning back.
public void dfs(Graph G, int v) {
    marked[v] = true;
    for (int w : G.adj(v)) {
        if (!marked[w]) {
            edgeTo[w] = v; // To remember the path
            dfs(G, w);
        }
    }
}

Breadth First Search (BFS)

BFS is used to solve the “Shortest Paths” problem in an unweighted graph. It finds the path with the fewest number of edges.

  • Concept: Explore neighbors first before moving to the next level of depth. This is used specifically to find the shortest path (in terms of number of edges) in an unweighted graph.
  • Tool: Uses a Queue (FIFO) to track which vertices to visit next.
  • Logic:
    1. Add starting vertex sss to a Queue and mark sss as visited.
    2. While the Queue is not empty:
      • Remove vertex v.
      • For each unmarked neighbor w of v: mark w, set edgeTo[w] = v, set distTo[w] = distTo[v] + 1, and add w to the Queue.
private void bfs(Graph G, int s) {
    Queue<Integer> q = new ArrayDeque<>();
    q.add(s);
    marked[s] = true;
    distTo[s] = 0;
    while (!q.isEmpty()) {
        int v = q.remove();
        for (int w : G.adj(v)) {
            if (!marked[w]) {
                edgeTo[w] = v;
                distTo[w] = distTo[v] + 1;
                marked[w] = true;
                q.add(w);
            }
        }
    }
}

Shortest Weighted Paths

Why BFS Fails on Weighted Graphs

BFS finds the shortest path in terms of the number of edges. However, in a weighted graph (like a map where edges represent miles), the path with the fewest edges might actually have a much higher total weight than a path with more edges.

  • Example: A direct flight (1 edge) that costs $500 vs. two connecting flights (2 edges) that cost $200 total. BFS would choose the $500 flight; a weighted algorithm would choose the $200 path.

Shortest Paths Tree (SPT)

The result of a single-source shortest path algorithm is often represented as a Shortest Paths Tree.

  • Definition: A tree rooted at the source sss that contains the shortest path from sss to every other reachable vertex in the graph.
  • Property: For VVV vertices, the SPT will have exactly V−1V-1V−1 edges.

Dijkstra’s Algorithm

Dijkstra’s is the standard algorithm for finding the SPT in a graph with non-negative edge weights. The core mechanism is relaxation, the process of updating the “best distance found so far” to a vertex.

  • Definition: If we find a path to vertex www through vertex vvv that is shorter than the current known path to www, we “relax” the edge v→wv \rightarrow wv→w by updating distTo[w] and edgeTo[w].
  • Performance: The runtime of Dijkstra using a Binary Heap is O(Elog⁡V)O(E \log V)O(ElogV), where each of the VVV vertices is added/removed once (Vlog⁡VV \log VVlogV) and each of the EEE edges might trigger a priority update (Elog⁡VE \log VElogV).
  1. Initialize distTo[source] = 0 and all other distTo values to ∞\infty∞.
  2. Insert all vertices into a Priority Queue (PQ) using their distTo values as priorities.
  3. While the PQ is not empty:
    • Remove the vertex vvv with the minimum priority.
    • For each outgoing edge v→wv \rightarrow wv→w, relax the edge:
      • If distTo[v] + weight(v, w) < distTo[w]:
        • Update distTo[w] and change its priority in the PQ.
        • Set edgeTo[w] = v.

A* Search (Heuristic-Based)

Dijkstra’s is a “uniform cost search”—it explores in all directions equally. A* (A-Star) is an optimization for finding the shortest path to a single target by using a heuristic.

  • Heuristic (hhh): An estimate of the distance from a node to the target (e.g., “straight-line distance” on a map).
  • Priority in PQ: Instead of just using distTo(v)distTo(v)distTo(v), A* uses distTo(v)+h(v)distTo(v) + h(v)distTo(v)+h(v).
  • Benefit: This “nudges” the search in the direction of the target, avoiding the exploration of nodes that are heading away from the goal.

Minimum Spanning Trees

  • Spanning Tree: A subset of the edges of a connected, undirected graph that connects all vertices together, without any cycles. For a graph with VVV vertices, a spanning tree always has exactly V−1V-1V−1 edges.
  • Minimum Spanning Tree (MST): A spanning tree where the sum of the edge weights is as small as possible.
  • The Cut Property: A fundamental rule used to find MST edges. Given any cut (a partition of the vertices into two non-empty sets), the minimum-weight edge that crosses the cut (has one endpoint in each set) must be part of the MST.

Prim’s Algorithm

Prim’s algorithm builds the MST starting from a single node and growing the tree one edge at a time. It is conceptually very similar to Dijkstra’s algorithm.

  • Mechanism:
    1. Start with an arbitrary vertex sss.
    2. Always add the cheapest edge that connects a vertex “in the tree” to a vertex “outside the tree.”
    3. Repeat until all vertices are in the tree.
  • Implementation: Uses a Priority Queue to track the cheapest edges crossing the current “cut” between the tree and the remaining vertices.
  • Runtime: O(Elog⁡V)O(E \log V)O(ElogV) using a binary heap.

Kruskal’s Algorithm

Kruskal’s algorithm builds the MST by considering all edges in the graph and adding the cheapest ones that don’t create a cycle.

  • Mechanism:
    1. Sort all edges in the graph by weight (smallest to largest).
    2. Iterate through the sorted edges. For each edge, add it to the MST unless it forms a cycle with edges already in the MST.
    3. Repeat until V−1V-1V−1 edges have been added.
  • The Cycle Check: To check for cycles efficiently, Kruskal’s uses the Disjoint Sets (Weighted Quick Union with Path Compression) data structure. If isConnected(u, v) is true, adding edge (u,v)(u, v)(u,v) would create a cycle.

Prim’s vs. Kruskal’s

While both find the same MST, they approach the problem differently:

  • Prim’s is like a “blob” that grows outward from a starting point.
  • Kruskal’s starts with many tiny “islands” (individual edges) that eventually merge into one giant continent.

Shortest Paths (Dijkstra) vs. MST (Prim’s)

It is common to confuse these two, but they solve different problems:

  • Dijkstra’s: Finds the shortest distance from Source →\rightarrow→ Target. It cares about the total path length from the start.
  • Prim’s: Finds the shortest distance from Tree →\rightarrow→ Target. It only cares about the weight of the single next edge to connect a new node.

Conceptual Comparison:

// Dijkstra Relaxation
if (distTo[v] + weight < distTo[w]) {
    distTo[w] = distTo[v] + weight;
}

// Prim's "Relaxation"
if (weight < distTo[w]) {
    distTo[w] = weight;
}

Directed Acyclic Graphs

  • Definition: A directed graph that contains no cycles.
  • Properties: In a DAG, you can never start at a vertex vvv and follow a sequence of directed edges that leads back to vvv.
  • Use Cases: Representing dependencies, such as course prerequisites, inheritance hierarchies, or task scheduling.

Topological Sort

The most important operation on a DAG is finding a Topological Order.

  • Definition: A linear ordering of vertices such that for every directed edge u→vu \to vu→v, vertex uuu comes before vvv in the ordering.
  • Algorithm (DFS-based):
    1. Perform a Depth First Search (DFS) on the graph.
    2. Whenever a vertex is “finished” (all its neighbors have been visited), add it to a list.
    3. The Reverse Postorder of this DFS is a valid topological sort.
  • Requirement: A topological sort is only possible if the graph is a DAG.

Shortest Paths in DAGs

While Dijkstra’s works on any graph with non-negative weights, we can find the shortest path in a DAG much faster using the topological order.

  • Algorithm:
    1. Find the Topological Sort of the DAG.
    2. Visit each vertex in that order and relax all its outgoing edges.
  • Advantage: Unlike Dijkstra’s, this approach works even if there are negative edge weights, provided the graph is a DAG.
  • Runtime: Θ(V+E)\Theta(V + E)Θ(V+E), which is faster than Dijkstra’s Θ(Elog⁡V)\Theta(E \log V)Θ(ElogV).

Longest Paths in DAGs

Finding the longest path has no known efficient solution is known. However, it is easy in a DAG.

  • The Trick (Negation): To find the longest path from sss to ttt:
    1. Multiply all edge weights by −1-1−1.
    2. Find the shortest path in this new graph using the DAG shortest path algorithm.
    3. Multiply the resulting distance by −1-1−1 to get the original longest path length.

Computational Complexity

  • P (Polynomial Time): Problems that can be solved quickly (e.g., Sorting, Shortest Path, MST).
  • NP (Nondeterministic Polynomial Time): Problems where a solution can be verified quickly, even if finding the solution is hard (e.g., Sudoku, Traveling Salesperson).
  • NP-Complete: The “hardest” problems in NP. If you find a fast way to solve one, you can solve all NP problems quickly.

Hashing I

Hash Tables is a data structure that allows for nearly constant-time (Θ(1)\Theta(1)Θ(1)) search, insertion, and deletion by mapping keys to array indices. The ultimate goal of a Set or Map is to find an item instantly.

  • Simple Case: If we only store integers 0−90-90−9, we can use a boolean array of size 10. exists[5] = true means 5 is in the set. This is Θ(1)\Theta(1)Θ(1).
  • The Problem: We can’t make an array large enough for every possible String, large integer, or custom Object.

Hash Functions and Hash Codes

To solve the size problem, we use a Hash Function to convert any object into a small integer index.

  • HashCode: A method (in Java, hashCode()) that converts an object into a 32-bit integer.
  • Modulo Operator (%): We use hashCode % array_length to fit that large integer into our actual array size.

Handling Collisions

A collision occurs when two different keys hash to the same index.

  • Separate Chaining (The Standard): Instead of storing a single item at each index, each index in the array points to a Link List (or “bucket”) of items.
  • Search Logic: To find “Apple,” hash it to index 3, then search the linked list at array[3] for “Apple.”

Two Pillars of Θ(1)\Theta(1)Θ(1)

To keep a Hash Table performing at constant time, two things must be true:

  1. Uniform Distribution: The hash function must spread items evenly across all buckets so no single list becomes too long.
  2. Resizing (Dynamic Growth): As we add more items (NNN), we must increase the number of buckets (MMM).
    • Load Factor (λ=N/M\lambda = N/Mλ=N/M): We keep the average bucket size small (e.g., λ<1.5\lambda < 1.5λ<1.5). When N/MN/MN/M exceeds this, we double MMM and rehash all items into the new, larger array.

Hashing in Java

In Java, every object inherits a .hashCode() method.

  • The Golden Rule: If x.equals(y), then x.hashCode() must be equal to y.hashCode().
  • Warning: If you override .equals(), you must override .hashCode(), or your object will “disappear” when put into a HashSet or HashMap.

Example Syntax:

public class Dog {
    String name;
    int age;

    @Override
    public int hashCode() {
        // Combines fields to create a unique-ish integer
        return Objects.hash(name, age);
    }
}
