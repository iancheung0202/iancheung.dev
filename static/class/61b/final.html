Hashing and Hash Tables

1. Conceptual Overview

Hash tables provide a way to implement the Set and Map ADTs with near-constant time performance. They avoid the requirement that objects be comparable (like in BSTs) by instead requiring them to be “hashable”.

  • Key Idea (Separate Chaining): Split one large list into MMM smaller lists (called buckets).
  • Collision: When two different items are reduced to the same bucket index.
  • Load Factor (λ\lambdaλ): Defined as N/MN/MN/M, where NNN is the number of items and MMM is the number of buckets.

2. Core Operations (Step-by-Step)

  • Add:
    1. Compute the object’s hashCode.
    2. Reduce the hashCode to a valid index (typically using modulus MMM).
    3. Search the corresponding bucket. If the item is not present, add it to the end of the chain.
  • Contains:
    1. Compute the object’s hashCode and reduce it to an index.
    2. Search the chain in that bucket. Return true if found, false otherwise.

3. Java Implementation Details

  • Default hashCode(): In Java, the default implementation returns the memory address of the object.
  • Custom hashCode() Requirements:
    • Determinism: If x.equals(y), then x.hashCode() must equal y.hashCode().
    • Consistency: The hash code should not change over time (important for immutable keys).
  • The equals Method: If you override hashCode, you must also override equals to ensure the table can correctly identify items within a bucket.

4. Dynamic Resizing

To maintain Θ(1)\Theta(1)Θ(1) average performance (worst case Θ(N)\Theta(N)Θ(N) if all items end up in one bucket), the number of buckets MMM must grow with the number of items NNN.

  • Trigger: Resize when the load factor N/MN/MN/M exceeds a constant threshold (e.g., 1.5).
  • Process: Create a new, larger array (usually doubling MMM) and rehash every item into the new buckets.

Tries (Retrieval Trees)

1. Conceptual Overview

A Trie is a specialized tree-based data structure used for storing Strings as keys.

  • Key Characteristics:
    • Each node stores exactly one character.
    • Nodes are shared by keys that share a common prefix (e.g., “sam” and “sad” share the “s” and “a” nodes).
    • Nodes must have a marker (e.g., a boolean isKey) to indicate if they represent the end of a complete word.

2. Trie Operations

  • Contains(String s):
    1. Start at the root. For each character in sss, follow the corresponding child link.
    2. Search Miss: If you “fall off” the tree (no link exists) or the final node is not marked as a key.
    3. Search Hit: If you reach the end of the string and the final node is marked as a key.
  • LongestPrefixOf(String word):
    • Traverse the Trie character by character. Keep track of the characters seen until you either reach the end of the word or hit a node with no corresponding child link.

3. Child Tracking Strategies

How nodes store links to their children affects performance and memory.

  • DataIndexedCharMap: Use an array of size RRR (alphabet size).
    • Pros: Fastest (Θ(1)\Theta(1)Θ(1) per character).
    • Cons: Extremely memory-intensive if the alphabet RRR is large.
  • BST/LLRB/Hash Table: Store child links in a secondary data structure.
    • Pros: More memory-efficient for sparse nodes.
    • Cons: Slightly slower lookup (Θ(log⁡R)\Theta(\log R)Θ(logR) for BST).

Why use Tries? They are theoretically faster than hash tables because there are no collisions to resolve, and they support prefix-based operations like keysWithPrefix or longestPrefixOf that hash tables cannot do efficiently.

Fundamentals of Sorting

Definitions & Requirements

  • Sorting: Rearranging an array into non-decreasing order.
  • Total Order: Sorting requires a total order on keys, satisfying:
    • Law of Trichotomy: For any aaa and bbb, exactly one of a<ba < ba<b, a=ba = ba=b, or a>ba > ba>b is true.
    • Law of Transitivity: If a<ba < ba<b and b<cb < cb<c, then a<ca < ca<c.
  • Inversion: A pair of indices i<ji < ji<j such that a[i]>a[j]a[i] > a[j]a[i]>a[j]. Sorting is the process of reducing inversions to zero.

Performance Metrics

  • Stability: A sort is stable if the relative order of equivalent items is preserved.
    • Example: If two students have the same name, a stable sort by section will keep them in their original relative name order.
  • In-Place: An algorithm is “in-place” if it does not require significant extra space (usually Θ(1)\Theta(1)Θ(1) or O(log⁡N)O(\log N)O(logN) for recursion).

Sorting Algorithms

Selection Sort

  • Strategy: Repeatedly find the minimum of the unsorted suffix and swap it into the next sorted position.
  • Runtime: Θ(N2)\Theta(N^2)Θ(N2) for all cases (best, worst, average) because it always scans the entire remaining unsorted portion.
  • Space: Θ(1)\Theta(1)Θ(1) (in-place).

Heapsort

  • Naive Heapsort: Add all items to a max-heap, then repeatedly delete-max into a new array.
    • Runtime: Θ(Nlog⁡N)\Theta(N \log N)Θ(NlogN).
    • Space: Θ(N)\Theta(N)Θ(N).
  • In-Place Heapsort:
    1. Bottom-up Heapify: Convert the array into a max-heap in-place using sink operations starting from the end (Θ(N)\Theta(N)Θ(N) time).
    2. Sortdown: Repeatedly swap the root (max) with the last unsorted slot and sink.
    • Runtime: Θ(Nlog⁡N)\Theta(N \log N)Θ(NlogN) (best case Θ(N)\Theta(N)Θ(N) if all items are duplicates).
    • Space: Θ(1)\Theta(1)Θ(1).
    • Note: Heapsort has poor cache performance compared to other sorts.

Mergesort

  • Strategy: Recursively split items into two halves, sort each half, and merge the sorted halves.
  • Runtime: Θ(Nlog⁡N)\Theta(N \log N)Θ(NlogN) for all cases.
  • Space: Θ(N)\Theta(N)Θ(N) due to the auxiliary array needed for merging.
  • Stability: Typically stable.

Insertion Sort

  • Strategy: For each index iii, swap a[i]a[i]a[i] leftward (into the sorted portion) until it is no longer smaller than its neighbor.
  • Runtime:
    • Best Case: Θ(N)\Theta(N)Θ(N) (already sorted).
    • Worst Case: Θ(N2)\Theta(N^2)Θ(N2) (reverse sorted).
  • Space: Θ(1)\Theta(1)Θ(1).
  • Performance Note: Best for small NNN or “almost sorted” arrays (where inversions are low).

Quicksort

  1. Pick a pivot item.
  2. Partition the array so everything less than the pivot is to its left and everything greater is to its right.
  3. Recursively sort the left and right partitions.

Partitioning Schemes

  • 3-Scan: Scans the array three times to build a new array of sorted partitions.
    • Space: Θ(N)\Theta(N)Θ(N).
    • Stability: Stable.
  • Hoare Partitioning: Uses two pointers walking toward each other, swapping items that are on the “wrong” side of the pivot.
    • Space: In-place (Θ(1)\Theta(1)Θ(1) extra space, O(log⁡N)O(\log N)O(logN) recursion stack).
    • Stability: Unstable.

Runtime and Worst-Case Avoidance

  • Average Runtime: Θ(Nlog⁡N)\Theta(N \log N)Θ(NlogN).
  • Worst-Case: Θ(N2)\Theta(N^2)Θ(N2) (occurs when pivots are consistently the smallest or largest items).
  • Avoidance Philosophies:
    1. Randomness: Shuffle input before sorting or pick random pivots.
    2. Smart Pivot Selection: Use the median of the first, middle, and last items (Median-of-3).
    3. Introsort: Switch to heapsort if the recursion depth exceeds a certain limit.

Counting Sort

  • Strategy: Count the occurrences of each key and use those counts to place items directly into their sorted position.
  • Runtime: Θ(N+R)\Theta(N + R)Θ(N+R) where NNN is items and RRR is the alphabet size.
  • Requirement: Keys must be from a small, discrete range.

LSD (Least Significant Digit) Radix Sort

  • Strategy: Sort items digit-by-digit from right to left using a stable counting sort as a subroutine.
  • Runtime: Θ(W⋅(N+R))\Theta(W \cdot (N + R))Θ(W⋅(N+R)), where WWW is the width of the longest key.
  • Stability: Must be stable to work.

MSD (Most Significant Digit) Radix Sort

  • Strategy: Sort items digit-by-digit from left to right, recursively sorting each resulting “bucket”.
  • Runtime: Best case Θ(N+R)\Theta(N + R)Θ(N+R); Worst case Θ(W⋅N+W⋅R)\Theta(W \cdot N + W \cdot R)Θ(W⋅N+W⋅R).
