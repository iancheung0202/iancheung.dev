CalVerify

A secure CalNet-integrated Discord verification bot that eliminates manual roster cross-referencing and stops unauthorized access to the UC Berkeley Official Discord server. This webpage is completely generated by AI based on this proposal document.

The Problem

Manual verification is broken

The current system relies on staff manually cross-referencing sensitive rosters (slow, error-prone, and insecure). Any non-Berkeley user only needs a student's publicly findable email and SID to gain access.

⚠️

Security Vulnerabilities

Students self-report email, name, and SID — all findable online. A bad actor can impersonate any current student to gain access to a private community server.

🐢

Manual & Error-Prone

Staff cross-reference rosters manually. This is time-consuming, delays engagement for new members, and Discord usernames are routinely confused with display names.

🔐

CalNet SSO Authentication

CalVerify authenticates students through CalNet, which is the same login used for CalCentral and bCourses. No self-reporting. Real identity, institutionally confirmed.

⚡

Fully Automated Role Assignment

The bot fetches graduation term directly from the Registrar's API and assigns the correct class role instantly, with a final moderator approval step before it goes live.

Technical Flow

Under the hood

Every step in the verification process, with the exact data, API calls, and database operations that make it work.

1

User clicks "Verify" Discord

The bot generates a random one-time token and maps it to the user's Discord ID in the PostgreSQL database. The token is short-lived (15 min TTL) and single-use only. We use this token to ensure other people cannot help verify accounts they don't own.

# Token generation (Python)
token = secrets.token_urlsafe(32)
db.execute("INSERT INTO verifications VALUES ($1, $2, NOW())",
  [token, discord_user_id])

# Bot sends this link to user
url = f"https://calverify.studentorg.berkeley.edu/verify?t={token}"
discord.py
2

User clicks the verification link OCF Backend

The Flask/FastAPI app hosted on OCF receives the request. It validates the token is active, then redirects the user to the CalNet CAS/OIDC endpoint with the app's registered client_id and a state parameter to prevent CSRF.

# Validate token, redirect to CalNet
@app.route("/verify")
def verify():
  token = request.args.get("t")
  row = db.get(token)
  if not row or row.expired:
    return "Invalid or expired link", 400
  return redirect(CALNET_OIDC_URL + f"?state={token}") Flask / FastAPI
Why OCF? — OCF is the only campus-affiliated infrastructure that supports long-running Python processes (24/7 uptime) while remaining within Berkeley's network security perimeter. Unlike Pantheon (PHP/WordPress, sleeps on inactivity) or Student Affairs IT (not designed for persistent bots), OCF runs standard Linux servers where discord.py, Flask, and PostgreSQL work natively. It's also free for SocReg-registered student orgs.
3

CalNet OIDC authentication CalNet SSO

The student logs into CalNet (with 2-Step MFA). Upon success, CalNet redirects back to the app's callback URL with an authorization code. The backend exchanges this for an ID token containing the student's UID, name, and email — scopes: openid profile email berkeley_edu_default.

# OIDC callback — exchange code for token
@app.route("/callback")
def callback():
  code = request.args.get("code")
  token_resp = oidc.fetch_token(code=code)
  claims = oidc.parse_id_token(token_resp)
  # claims: {uid, name, email, sub}
  uid = claims["berkeley_edu_uid"] OIDC / CAS
4

Query the Student API Registrar API

The backend calls the UC Berkeley Student Information Services (SIS) API using an App Key to retrieve the student's expected graduation term and academic status. If the API returns a result, the student is confirmed enrolled. If not, verification is rejected.

# Call SIS Student API (P3 data: UID + grad term)
resp = requests.get(
  f"https://apis.berkeley.edu/sis/v1/students/{uid}/academics",
  headers={"app_id": APP_ID, "app_key": APP_KEY}
)
plans = resp.json()["academicStatuses"][0]["studentPlans"]
grad_term = plans[0]["expectedGraduationTerm"]["name"]
# e.g. "Spring 2029" SIS Student API

Update the database PostgreSQL

The verification record is updated with the student's UID, name, email, graduation term, and academic status. This record is P3 data — stored on campus in OCF servers and never in a third-party system.

Security & Privacy

Defense in depth

CalVerify handles P3 FERPA-protected data and must meet UC Berkeley's MSSEI standards. Here's how each threat is mitigated.

One-Time Tokens

Each verify link contains a cryptographically random 256-bit token (via secrets.token_urlsafe). Tokens expire in 15 minutes and are invalidated on use — no replay attacks.

CSRF Prevention

The token is passed as the OIDC state parameter. The callback validates state matches before processing any authentication response.

Rate Limiting

Per-IP rate limiting on the /verify and /callback endpoints prevents brute force and DDoS. Failed attempts trigger exponential backoff.

Minimal Data

Only P3 Directory Data is stored: CalNet UID, name, email, graduation term, and academic status. No SID, phone numbers, or addresses. Only what's needed to assign one Discord role.

On-Campus Hosting

All data stays within OCF's servers — the same infrastructure used by Berkeley departments. No third-party cloud (AWS, Heroku, Render). Meets MSSEI P3 compliance.

Audit Logging

All verification events, moderator actions, and API calls are logged with timestamps and Discord user IDs, enabling full audit trails for compliance and moderation review.
