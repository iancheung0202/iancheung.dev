Union-Find (Disjoint Sets)
// 4 versions: Quick Find → Quick Union → Weighted QU → + Path Compression
Quick Find — find & union
  • id[p] — return the value at index p. O(1)
  • Loop all elements. For every i where id[i] == id[p], set id[i] = id[q]. O(N)
  • Union is slow — must touch every element
Array stores group label directly. Union rewrites entire group.
Quick Union — find & union
  • Follow parent pointers until id[i] == i (self-loop = root). O(N) worst
  • Find root of p, find root of q. Set id[root(p)] = root(q). O(N) worst
  • Tree can become a chain (height N)
Array stores parent index. Root = index points to itself.
Weighted QU — union by size
  • Same as QU: follow parents to root. O(log N)
  • Find both roots. Always attach smaller tree under larger tree's root.
  • Keep a size[] array. Update size of new root: size[bigRoot] += size[smallRoot]
  • Guarantees tree height ≤ log N
Negative values in array = root (value = -size). Positive = parent index.
Path Compression — during find()
  • Call find(p) as normal — walk up to root
  • On the way back down (or in a second pass), re-point every visited node directly to root
  • Next find() on those nodes is now O(1)
  • Does NOT change who the root is — only flattens paths
WQU + Path Compression ≈ O(α(N)) per op — nearly O(1) amortized
KEY MENTAL MODEL: The array stores a tree. Negative = you're the root (store -size). Positive = your parent's index. Union always connects roots. Find always returns the root.
Binary Search Tree
// left < root < right invariant must hold at every node
Search / Contains
  • Start at root
  • If key == node.key → found ✓
  • If key < node.key → go LEFT
  • If key > node.key → go RIGHT
  • If null → not found ✗
Best O(log N) Worst O(N)
Insert
  • Search for the key (same as above)
  • When you reach null, insert new node here
  • New node is always a leaf
  • Never rearranges existing nodes
Insertion order determines tree shape. Sorted input → O(N) height chain.
Delete (Hibbard)
  • 0 children (leaf): Just remove it. Parent points to null.
  • 1 child: Replace node with its only child. Bypass it.
  • 2 children: Find the successor (smallest node in RIGHT subtree) OR predecessor (largest in LEFT subtree)
  • Copy successor's key/value into current node
  • Delete the successor (it has ≤ 1 child, so use case 1 or 2)
Successor = go right once, then go left as far as possible
Min / Max / Floor / Ceiling
  • Go LEFT until null → that's your min
  • Go RIGHT until null → that's your max
  • Largest key ≤ target: go left if key > target, else save node and go right
  • Smallest key ≥ target: go right if key < target, else save node and go left
B-Tree (2-3 Tree)
// all leaves at same depth · nodes hold 1 or 2 keys (for 2-3 tree) · never insert into empty node
Search
  • At each node, compare key against all keys in the node
  • If match → found
  • If key < left key → go to leftmost child
  • If key between two node keys → go to middle child
  • If key > all node keys → go to rightmost child
  • If leaf with no match → not found
Insert
  • Search to find the correct leaf node
  • Add the key into that leaf (may now have 2 keys — that's fine)
  • If node now has 3 keys (overfull) → SPLIT:
  • Push the middle key UP to the parent
  • Left key stays as left child, right key stays as right child
  • If parent is now overfull → repeat split upward
  • If root splits → new root is created (tree grows UP, never down)
Height only increases when the ROOT splits. Tree grows from top.
CORE INVARIANT: Never place a new key into an empty node. Always add to an existing leaf, then split upward if needed. This guarantees all leaves stay at the same depth.
LLRB (Left-Leaning Red-Black Tree)
// red links represent 3-nodes (glued pairs) · isomorphic to 2-3 tree · always insert as RED
MENTAL MODEL: Red link = the two nodes it connects are a single 3-node. Black height = number of black links. Every root-to-leaf has the same black height. Red links always lean LEFT.
rotateLeft(h)
  • h.left is black AND h.right is RED (right-leaning red — fix it)
  • Let x = h.right
  • h.right = x.left
  • x.left = h
  • x.color = h.color (x inherits h's color)
  • h.color = RED
  • Return x (x is the new top)
Fixes: right-leaning red link → makes it left-leaning
rotateRight(h)
  • h.left is RED AND h.left.left is RED (two reds in a row on left)
  • Let x = h.left
  • h.left = x.right
  • x.right = h
  • x.color = h.color
  • h.color = RED
  • Return x
Fixes: two consecutive left-red links → temporarily makes a 4-node
colorFlip(h)
  • h.left is RED AND h.right is RED (both children red = 4-node, must split)
  • h.color flips (BLACK → RED)
  • h.left.color flips (RED → BLACK)
  • h.right.color flips (RED → BLACK)
Equivalent to pushing middle key UP in a B-Tree split. h becomes red (passes the "problem" up)
Insert — full process
  • Search for spot exactly like BST (left if smaller, right if bigger)
  • Insert new node with a RED link (always)
  • On the way back up (recursive return), apply fixes:
  • if right.RED && !left.RED → rotateLeft
  • if left.RED && left.left.RED → rotateRight
  • if left.RED && right.RED → colorFlip
  • Root is always set to BLACK at the end
All 3 checks happen every time on every node during unwinding. Order matters.
INVARIANTS: (1) No right-leaning reds. (2) No two consecutive left reds. (3) Root is black. (4) No red-red on right. Rotations preserve black-height. ColorFlip passes the "split" upward.
Heap (Min-Heap)
// complete binary tree · parent ≤ both children · stored in array: parent(k)=k/2, left=2k, right=2k+1
Insert (swim up)
  • Add new element at the bottom-rightmost open spot (end of array, index = size+1)
  • Swim up: compare with parent (array[k/2])
  • If new node < parent → swap with parent
  • Repeat from new position until node ≥ parent OR reach root
O(log N)
Swim = bubble UP. Always start from bottom.
removeMin (sink down)
  • Save the root (index 1) — that's your min to return
  • Move the last element (bottom-right) to the root position
  • Remove the last element (shrink size)
  • Sink down: compare root with both children
  • Swap with the smaller child (if smaller than root)
  • Repeat from new position until node ≤ both children OR reach leaf
O(log N)
Always swap with SMALLER child (not just any child smaller than you)
Heapify (bottom-up, in-place)
  • Start at the last non-leaf node: index N/2
  • Sink that node down
  • Move to N/2 - 1, sink it down
  • Continue leftward/upward until you sink the root
O(N) not O(N log N)!
Heap Sort
  • Phase 1: Heapify array into a MAX-heap (bottom-up, O(N))
  • Phase 2: Repeatedly: swap root (max) with last unsorted element
  • Shrink the heap boundary by 1
  • Sink the new root down
  • Repeat N-1 times → array is sorted ascending
O(N log N) O(1) space NOT stable
Graph Traversals — DFS & BFS
// DFS uses a stack (recursion) · BFS uses a queue · both mark visited to avoid cycles
DFS — Depth First Search
  • Mark source as visited
  • For each neighbor of current node:
  • If NOT visited → recursively DFS from neighbor
  • When all neighbors done → backtrack (return)
PRE-ORDER
Visit node before recursing into children
POST-ORDER
Visit node after all children return
Uses implicit call stack. Explores as DEEP as possible before backtracking.
O(V+E)
BFS — Breadth First Search
  • Create a Queue. Add source. Mark source visited.
  • While queue is not empty:
  • Dequeue node v
  • For each neighbor of v: if NOT visited → mark visited, enqueue neighbor
Explores all nodes at distance 1, then distance 2, etc. Finds SHORTEST PATH (unweighted).
Mark visited when ENQUEUING, not when dequeuing, to avoid duplicates in queue
O(V+E)
DFS — Tree Traversal Orders
  • Pre-order: Root → Left → Right
  • In-order: Left → Root → Right (gives BST sorted order)
  • Post-order: Left → Right → Root
  • Level-order: BFS — left to right, level by level
Multi-Source BFS
  • Add ALL source nodes to queue at the start
  • Mark ALL of them as visited immediately
  • Run BFS normally
  • Finds shortest distance from ANY source to each node simultaneously
Dijkstra's Algorithm
// single-source shortest path · weighted graphs · NO negative edges
Algorithm — Step by Step
  • Set distTo[source] = 0, all others = ∞
  • Add ALL vertices to a min-heap PQ keyed by distTo
  • While PQ is not empty:
  • Pop vertex v with MINIMUM distTo (it's now finalized)
  • For each edge (v → w) with weight e:
  • If distTo[v] + e < distTo[w] → RELAX:
  • Update distTo[w] = distTo[v] + e
  • Update edgeTo[w] = v (for path reconstruction)
  • Update w's priority in PQ
Once a vertex is popped from PQ, its distance is FINAL. Never re-visit.
Key Concepts
  • Relax = check if going through v gives w a shorter path
  • Greedy: always process the closest unvisited vertex next
  • Fails with negative edges — a later shorter path could contradict a finalized node
  • PQ stores (vertex, distance). changeKey when you find shorter path.
O((V+E) log V)
vs. BFS
BFS = shortest by hops (unweighted). Dijkstra = shortest by total weight.
vs. Prim
Dijkstra tracks total path cost. Prim tracks single edge cost to MST.
Minimum Spanning Tree — Prim & Kruskal
// MST connects all V vertices with V-1 edges at minimum total weight · no cycles
CUT PROPERTY (theoretical basis for both algorithms): For any cut of the graph (partition into two sets), the minimum-weight crossing edge must be in the MST.
Prim's Algorithm
  • Start with any vertex. Add it to MST.
  • Add all its edges to a min-heap PQ (keyed by edge weight)
  • While PQ not empty AND MST has fewer than V vertices:
  • Pop the minimum-weight edge (u → w)
  • If w is already in MST → skip (would create cycle)
  • If w is NOT in MST → add w to MST, add edge to result
  • Add all edges from w to non-MST vertices into PQ
Grows the MST one vertex at a time. Always picks cheapest edge INTO the current MST.
O(E log V)
Kruskal's Algorithm
  • Sort ALL edges by weight (ascending)
  • Initialize Union-Find with all V vertices
  • For each edge (u, v) in sorted order:
  • If find(u) != find(v) (different components, no cycle):
  • Add edge to MST
  • union(u, v)
  • Stop when MST has V-1 edges
Greedily picks cheapest edge globally that doesn't create a cycle. Uses Union-Find to detect cycles.
O(E log E)
Prim vs Kruskal — When to use
  • Prim = better for dense graphs (many edges)
  • Kruskal = better for sparse graphs (few edges)
  • Both always find the MST
  • If all edge weights are unique → Prim and Kruskal find the same unique MST
Prim vs Dijkstra — Key Difference
  • Dijkstra: PQ key = total distance from source
  • Prim: PQ key = weight of single edge connecting to MST
  • Code is nearly identical — only what you store in PQ differs
  • Dijkstra → shortest path tree. Prim → minimum spanning tree.
DAGs & Topological Sort
// Directed Acyclic Graph · topological order = linear ordering where u comes before v for every edge u→v
Topological Sort — Reverse DFS Post-order
  • Run DFS on the entire graph (visit all vertices)
  • Use POST-order: when DFS fully finishes a vertex (all descendants done), add it to a stack
  • After DFS completes, pop the stack → that's your topological order
Post-order DFS naturally finishes "later" nodes first. Reversing gives correct topo order.
O(V+E)
Shortest Path in DAG
  • Run topological sort
  • Process vertices in topological order
  • For each vertex v (in topo order), relax all outgoing edges
  • Works because in topo order, when we process v, all predecessors are already finalized
O(V+E)works with neg edges!
Longest Path in DAG
  • Negate all edge weights
  • Run shortest path algorithm
  • Negate results
  • Works ONLY in DAGs — no negative cycles possible
Longest path on general graphs is NP-Hard. Only solvable on DAGs.
Detecting a Cycle
  • DFS with 3 states: UNVISITED, IN_PROGRESS, DONE
  • If you reach an IN_PROGRESS node → cycle detected!
  • If DFS completes with no IN_PROGRESS hits → graph is a DAG
Topological sort only works on DAGs. If cycle exists, no valid topo order exists.
Algorithm Choice Summary
  • Unweighted shortest path → BFS O(V+E)
  • Weighted, no negatives → Dijkstra O(E log V)
  • DAG (any weights) → Topo + Relax O(V+E)
  • Negative edges, general → Bellman-Ford O(VE)
  • Minimum spanning tree → Prim or Kruskal
